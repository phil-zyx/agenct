# 三人协作最小闭环：验收规格

基线：`master` @ `00aff3a68206d17788c80ba2b600a66377e6b6c2`（2026-11-11 核对）。本文是验收门槛，不是已完成功能清单。

## 1. 验收对象与边界

场景：Alice 发起「完成一份经过审阅的发布说明」；Bob 负责初稿；Carol 负责审阅。三人各用自己的账户和助手。需要同一个明确目标、可见的分工与进展，经过一次范围变更、一次阻塞、一次退回，最终由指定发起人验收。相同流程分别验证临时项目和持续项目。

Eve 是隔离探针，不是第四个参与者。所有内容均为合成测试数据，不使用真实私聊、密钥或线上账户。

必须区分四层证据：

1. 单元测试：只证明局部状态/权限判断。
2. 真实 Hub + SQLite + HTTP + Mock 模型：证明实际 API、持久化及恢复；不证明浏览器交互或真实模型质量。
3. 三个隔离浏览器上下文连接真实临时 Hub：证明交互、各身份同步、刷新和导航行为；不等于三台设备试用。
4. 三位真人各自设备完成一次临时项目和一次持续项目：生产式体验证据，另记实际网络/服务版本；不由前面三层代替。

**通过两个具有相同摘要的双人任务，不等于通过三人共同项目。** 项目成员资格也不自动授予既有双人任务正文、历史、材料、草稿或私聊的访问权限。

## 2. 当前基线能做什么

- 双人委派提案只有发起人可见；确认后生成双人任务。
- 接手、交付、退回、验收受参与者身份和 `expected_revision` 约束。
- 退回保留已提交版本，下一次交付追加版本。
- 草稿、修改要求和个人背景仅属于本人；正式交付由本人确认。
- 联系人消息、提案、聊天和草稿各有请求键或回执机制。任务动作不是同样的回执协议：重试旧版本得到 409，必须先读取当前状态。

基线上尚不存在：共同项目对象/成员邀请、共同目标版本变更、项目级结构化阻塞、依赖关系、共享项目 UI、项目最终验收与归档完整闭环。项目基础模型属于独立实现；未经其准确提交的实测，不将其标为已通过。新增脚本的 `--scope foundation` 针对该实现的 API 合约，基线上无这些 API，因此运行该模式会明确失败。

## 3. 可执行的前置回归

新增 `scripts/three-person-acceptance.cjs` 使用 Node 标准库，启动一个仅监听 loopback 的临时 Hub，使用四个随机测试令牌、独立 SQLite、显式 Mock 模型，并关闭自动起草。不会连接已运行服务、读取真实凭证或调用提供商。终止后清理临时数据。

```sh
cargo build --locked --manifest-path hub/Cargo.toml
node scripts/three-person-acceptance.cjs --scope prerequisites
# 项目基础模型实现后单测 API，或用 --scope all 连同前置回归运行。
node scripts/three-person-acceptance.cjs --scope foundation
# 测其他 checkout 的准确构建时显式指定；请同时记录其 commit。
AGENCT_TEST_HUB_BINARY=/absolute/path/to/agenct-hub node scripts/three-person-acceptance.cjs
```

通过时输出 `PASS [prerequisite]`，末尾明确标注不认证共同项目或真人设备。找不到二进制、API 返回错误、状态不符均退出非零；没有跳过未实现步骤或将 404 视作通过的逻辑。脚本没有被加入既有 `npm test`，避免把前端无构建检查变成隐式启动服务。

| 编号 | 自动化前置检查 | 可证明的范围 |
| --- | --- | --- |
| P01 | Alice/Bob/Carol 独立身份；未知身份 401；私聊/偏好标记不得出现在其他人的消息/公开资料 | 服务端身份及个人信息投影 |
| P02 | 两个同目标提案仍仅 Alice 可见；未确认前所有任务列表为空；相同请求重试不重复，换接收人返回 409 | 提案边界，不是项目共享 |
| P03 | 明确委派后 Alice 两项、Bob/Carol 各一项、Eve 零项；跨任务读写 404；伪造 actor 422 | 三个参与者之间的双人 ACL |
| P04 | Bob 私密起草、同键重放；Alice/Carol/Eve 无权读草稿或回执；交付数仍为零 | 起草不等于共享或交付 |
| P05 | 交付 v1 → 退回 → 重新接手 → v2；旧 revision 409；两个并发交付恰好一个成功、一个 409 | 防旧确认和双提交，历史版本保留 |
| P06 | HTTP 代理先截断未转发请求，再截断已提交消息的响应；杀死/重启临时 Hub；重试原请求无重复、改正文 409 | 真实 HTTP 故障切点和消息持久幂等 |
| P07 | Carol 交付成功后丢响应；杀死/重启；GET 证实结果已保存；旧 revision 重试 409、不增交付；本人和发起人完成验收 | 不确定交付后的只读核对与持久历史 |

P06/P07 的故障是进程与 HTTP 层；未模拟浏览器后台节流、移动端断网、提供商在请求中途失联或机器断电。幂等声明只针对 Hub 的记录与动作，不声称外部模型 exactly-once。

## 4. 项目基础模型门槛

`--scope foundation` 已实现 F01–F06 的核心 HTTP 场景：两种项目类型、邀请接受、同意前隐藏/同意后最小投影、撤销关联、退出再加入不恢复共享、移除、并发归档及多次进程重启；仍需在准确实现提交上执行。F04 的不同项目重新共享、F07 的 OIDC 租户和 F08 的账号吊销不在该模式覆盖范围内。

这些用例应在独立项目模型实现后，使用真实 Hub 按其公开 API 执行。预期 API 为 `/api/projects`、成员邀请/接受/退出和任务关联。接口响应以该实现文档为准，不能在测试中直接改数据库代替真实操作。

| 编号 | 步骤 | 必须观察的结果 |
| --- | --- | --- |
| F01 共同目标 | Alice 创建 temporary 项目，再建 ongoing 项目，写入相同业务目标；同 `request_id` 重试一次，再改正文重试 | 首次每种类型仅一项目；同内容返回同 ID；键冲突不创建新项目；两种 kind 不混淆 |
| F02 三身份加入 | Alice 邀请 Bob/Carol；两人分别查看邀请、接受；Eve 直接访问项目 ID | 未接受前仅看到邀请预览，不能读取项目内容；接受后各自身份与成员状态准确；Eve 无列表条目且直接读取拒绝 |
| F03 共享范围 | 将 Alice→Bob、Alice→Carol 的已存在任务关联到项目；只做一方确认，再由另一方确认 | 单方操作不能暴露任务；双方明确同意后，只公开已确认字段；非参与者的任务正文、材料、历史和草稿 API 仍拒绝；label 如来源于摘要也必须在同意范围内 |
| F04 不同意共享 | Bob 拒绝第一项关联；重试旧邀请；在另一项目重复关联并改变共享字段 | 无隐式同意、无旧请求复活、无扩大字段范围；拒绝不损害原双人任务 |
| F05 退出/移除 | Carol 退出项目；Alice 移除 Bob；两人用旧页面/旧版本继续读写 | 新请求立即拒绝项目访问；项目列表不再展示；已有本人双人任务的权限依据原任务规则，不被默认删除或扩大；旧邀请不可自动重新加入 |
| F06 并发与重启 | 同项目 revision 并发发两次写操作；丢成功响应；重启 Hub；读取再决定是否重试 | 不发生覆盖或重复成员/关联；版本单调；可以确定最终已提交状态，无法确定时明确不确定，不猜测失败 |
| F07 组织边界 | 同 tenant 的三人完成加入；另一个 tenant 的账户探测邀请/项目/关联 | 跨组织拒绝；错误、搜索结果、项目预览不得泄露目标或人员关系；无租户配置时的测试不能代替本项 |
| F08 权限降级 | 成员失效/令牌吊销后，用未关闭的会话与旧链接操作 | 服务端重新检查账号/目录权限；不得只靠 UI 隐藏按钮；持久邀请/成员资格不能绕过账号禁用 |

## 5. 完整三人闭环门槛（未实现项不得跳过）

以下是目标体验验收，不得用现有联系人消息或取消任务冒充结构化实现。

### T01 共同目标与责任

- Alice 用明确目标、成果、验收条件创建项目，邀请 Bob/Carol；三人各自确认加入。
- 三个独立浏览器在同一项目看到同一个项目 ID、相同的已确认目标版本、自己与他人的共享职责。
- 每项工作有明确负责人和验收人。助手消息明确标识助手，不能冒充本人接手或承诺。
- 私聊中的额外背景不会出现在共同目标、项目摘要或其他人的助手上下文。

### T02 变更与过期确认

- 在 Bob 正在编写、Carol 已打开旧验收卡片时，Alice 提出将目标由 v1 改为 v2，并写明变更内容与影响。
- 未确认的建议不改变共同目标；确认后新目标有版本、作者和时间，旧目标保留。
- 三人看到变更提醒。对受影响任务需要重新确认，不能将旧草稿、旧交付或旧验收悄悄绑定到新目标。
- Carol 在旧卡片点击确认，服务器拒绝旧版本并要求读取新状态。仅浏览器提示不算通过。
- 当前基线没有共同目标更新接口，因此本项仍为未实现，不能用修改未确认提案替代。

### T03 阻塞与恢复

- Bob 将任务标为阻塞，明确写入「缺少发布日期」、需要 Alice 补充、阻塞起点与相关工作。
- Alice/Carol 看到共享阻塞，但不会看到 Bob 为解释原因而写在私聊里的内容。
- 缺少原因/无权者发起阻塞应被拒绝；重复提交不能重复创建阻塞记录。
- Alice 补充已确认材料，Bob 解除阻塞；保留起止历史，等待期间不自动交付、验收或算作完成。
- 刷新、离线再连接和重启后仍能回答「谁在等谁、需要什么、下一步由谁做」。
- 当前基线没有 blocked 状态/事件模型，因此不能以取消、聊天文字或待接手状态作为本项通过证据。

### T04 审阅退回、再交付与整体验收

- Bob 提交自己审阅过的初稿；Carol 在获授权的共享成果范围内审阅。共享成果不包括私人草稿历史。
- Carol 提出修改意见，指定有权限的验收人正式退回；不默认赋予第三人原双人任务的 return/approve 权限。
- 退回记录包含与本轮成果绑定的共享理由；Bob 重新接手，提交 v2，v1 保留可比较。
- 任一贡献仍阻塞/退回/未验收时，项目不能无提示宣称全部完成。
- 最终由指定验收人按当前目标版本确认结果。重复确认无重复记录；过期确认不得通过。
- 临时项目完成后可归档且历史可读取；持续项目可继续创建下一轮任务，不能抹去上一轮成果/验收。

### T05 浏览器故障与身份隔离

- 三个浏览器上下文分别登录，不用同一个页面切换名字假装三人。
- 在发送前断网、提交后丢响应、刷新、Close/Cancel、Back/Forward、多次点击、Hub 进程重启分别重复关键写操作。
- 前端保留未发送输入；不确定结果先查询回执/状态，不自动用新键重发或声称失败。
- Bob 退出后用同一浏览器登录 Carol：本地缓存、延迟响应、项目卡片、草稿和恢复提示不得重新显示 Bob 的私人内容。
- 在撤销成员资格/项目归档后用旧页面操作，服务端拒绝非法动作。
- 后台通知与真实三设备网络延迟另测，记录实际值，不预设必定 5 秒内送达。
