# 个人助手与成员协作

Agenct 连接团队成员及各自的助手。个人私聊用于讨论和准备；联系人会话用于双方沟通；需要明确交付的事情进入委派、接手、交付和验收流程。

## 配置自己的协作资料

直接在与自己助手的聊天中说明要记住或修改的内容。例如：

- 「记住：我负责支付服务，回复先给结论。」
- 「把我的职责公开为支付服务。」
- 「允许助手用公开资料答复。」
- 「关闭自动起草。」

助手会把识别到的修改整理为待确认卡片，列出准备修改的内容及可见范围。点击「确认记住」后才更新资料或授权；点击「暂不保存」不会修改资料。普通聊天不会把个人背景自动公开给同事。

想调整候选内容时点击「继续修改」，再在输入框里说清楚要改成什么。这个按钮只准备输入，不会自动发送或保存。新建议生成后会替代旧的待确认建议，仍须确认。刷新页面会重新显示当前账户尚待确认的卡片。如果资料已经在其他页面更新，旧建议不能覆盖新资料，需要重新说明修改内容。

「助手记住的我」展示当前已经保存的内容。这里是只读资料页，点击「通过聊天修改」会返回私聊并准备输入；不会自动发送消息。资料分为三个区域：

- **同事可见的资料**：团队、职责、可以找你帮忙的事情，以及发起请求时应提供的材料。只有有权联系你的成员能够读取，仍受账号状态与组织边界限制。
- **仅自己可见的背景和偏好**：工作背景、回复偏好。它们不出现在联系人资料和共享会话中。这里不用于保存 API 密钥或服务密码。
- **助手代办范围**：是否允许助手依据公开资料答复，以及接手任务后是否自动准备私密草稿。

公开资料答复默认关闭。确认开启后，助手可以回答关于职责、可提供帮助和请求材料的明确询问；回复会标明助手身份。当前采用限定范围的公开资料答复，不会读取私聊来回答，也不会替本人承诺接手或截止时间。

自动准备私密草稿默认开启，同时受服务端的自动起草开关控制。确认关闭自动起草后，不再启动新的自动起草；仍可由本人主动请求起草。已经启动的模型请求不会因为之后修改设置而撤回。

保存前请核对候选卡片，特别是公开资料和助手权限。已经保存的资料和待确认建议都只属于当前账号，退出并切换账号后不会显示上一位用户的内容。

## 与同事沟通

在联系人中选择成员，查看对方的协作资料，然后发送消息。会话只对双方开放；对方助手的回复和本人消息有不同身份标识。

消息显示已发送只代表服务已保存，不代表对方本人已读、接手或承诺完成。联系人会话和「我与助手」的私聊分别保存，打开联系人不会自动转发个人私聊。

可先用消息问清楚需求。需要一个明确结果时，选择请对方帮忙，整理任务摘要并生成提案。此时提案仍仅自己可见；核对接收人、摘要和共享材料后确认，才创建双方可见的任务。

## 完成一次交接

1. 发起人整理目标、需要的结果与必要材料，确认共享并委派。
2. 接收人确认接手。助手可按个人设置准备私密草稿，其他人看不到草稿和修改要求。
3. 接收人审阅、修改后预览并确认交付。只有这次明确提交的内容成为双方可见的结果。
4. 发起人验收；需要修改时退回，接收人重新接手、继续处理并再次交付。

轻量消息不强制创建任务。任务接手、正式交付和验收仍由本人操作。发送失败或响应中断时，保留输入并重试同一次请求，不重复创建消息或提案；如果任务状态已被另一页面修改，应重新读取状态后操作。

## 当前边界

- 联系人范围来自当前服务的成员和组织配置，不支持搜索并添加任意外部用户。
- 联系人会话当前显示最近 100 条消息，尚未提供更早历史的翻页入口。
- 个人助手尚不支持自由协商截止时间、自动接受任务、自动交付或自动验收。
- 公开资料答复不等同于通用的后台 Agent 对话；尚不自动追问任意缺失材料或持续催办。
- 私密是应用内的可见范围。使用真实模型时，个人助手处理内容仍会经过已配置的模型服务，并非完全离线。
- GitLab 登录提供身份。Issue/MR 自动创建、任意工具执行及自动发布不属于本轮能力。

## 本地验收

先构建 Hub，再运行双浏览器测试：

```sh
cargo build --locked --manifest-path hub/Cargo.toml
node hub/web/collaboration.browser.test.cjs
node hub/web/profile-chat.browser.test.cjs
```

测试启动独立的临时数据库与本地 Mock Hub，并使用隔离的浏览器会话验证聊天修改资料时的确认、取消、冲突与账户隔离，以及成员消息、助手身份、重试、委派到验收和移动端。不会调用真实模型，不会修改已运行服务中的账户或任务。测试身份只用于验收，不会加入 GitLab 登录环境。
