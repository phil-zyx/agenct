# 架构与信任边界

## 两条独立运行路径

- `dist/` 是浏览器内脚本模拟：预设规则、localStorage、虚构角色和证据。所有角色数据在同一浏览器，过滤不是隐私隔离。已托管的静态演示不等于下述后端已部署。
- `hub/` 是 Rust/Axum 单进程开发服务：单窗口聊天 → 开发令牌身份 → SQLite 私聊、委派提案、任务和个人配置。只监听 loopback。身份隔离由服务端执行，但不是生产账号或多租户系统；主机管理员仍可读取数据。

## 已连接的服务端流程

1. Hub 依据 bearer token 决定身份，客户端不能指定请求者。私聊按身份隔离，适配器只收到该用户已完成的聊天历史。
2. 运行模式必须明确选择 `mock` 或 `dsh`，失败不会退回 mock。mock 是确定性测试替身；DSH Python 适配器包含真实 SDK 调用路径，但尚无真实提供商调用验收。
3. 模型只能返回回复及可选的结构化委派提案。Hub 严格检查字段、当前消息中明确提及的已配置接收者和原文摘要。提案仅发送者可见；用户确认后原子创建共享任务，不复制私聊历史。
4. 提案创建支持请求键，确认/拒绝支持修订检查与重放。兼容接口 `POST /api/tasks` 仍允许认证用户直接创建任务，没有提案确认和幂等保证；不能宣称全部入口都强制执行提案审批。普通模型聊天也不能自动重试。
5. 接收者人工接单并提交人工结果，请求者验收或退回。状态变更检查身份、状态及修订号。任务验收不是代码、产物或 CI 的独立核验。
6. UI 在可见时轮询更新，具备退避、读请求超时和退出登录后的旧响应隔离；不是推送服务或浏览器通知。真实浏览器验收仍待完成。
7. 个人 Agent 配置按用户存入 SQLite，固定角色、最多 8 个配置、一个启用的协调者，模型引用仅 `server-default`。配置不调度 Agent、不改变模型路由，也不接收密钥；尚无配置 UI。

详细操作见 [Hub 指南](rust-hub.md)、[DSH 适配器](dsh-adapter.md)及[个人配置](personal-profiles.md)。

## 已实现但未接入聊天运行链路的库

- **Worker 队列**：持久任务、幂等入队、租约与过期隔离、撤销和次数上限、候选提交及检查合同。没有面向用户的运行接口或启动中的消费服务。
- **消费与发布合同**：包含消费脚手架、显式发布授权和不确定结果台账。内置 Docker 执行及 Python 成功证据生成已禁用，因为不可信仓库测试能影响原核验流程；目前不能执行代码。候选摘要哈希不等于可信测试证明。
- **GitLab 传输**：限定 HTTPS 来源与项目，草稿 MR、精确 SHA 的分支/流水线读取及不确定结果核对。没有分支上传、合并、审批或自动重试；未连入 Hub，不能绕过可信证据与用户授权直接启用。

见 [Worker 合同](worker-contract.md)、[执行器边界](executor-integration.md)及 [GitLab 传输](gitlab-transport.md)。这些库的离线测试不证明真实隔离、真实 TLS、远端发布或 CI 成功。

## 部署与剩余信任边界

[私有试运行工具](private-staging.md)提供 loopback 启动、独立开发令牌、私有状态目录和 SSH 转发说明；没有创建云主机、安装远端服务或提供可访问的后端 URL。

要完成真实链路，仍需生产身份和租户策略、密钥与模型绑定、真实 DSH 验收、独立可信证据采集与隔离执行、授权的分支上传及 GitLab 联调、浏览器与远端部署验收。Worker 不应持有发布凭据；模型不能决定权限；发布必须重新检查任务修订、精确提交和授权；未知外部结果必须先核对。日志保留、备份恢复、配额及安全审查也仍需完善。不得将模拟数据或库合同称为这些能力已上线。
