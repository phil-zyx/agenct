# 架构与信任边界

## 当前原型

浏览器 UI 调用本地 JavaScript 状态机，消息和任务写入 localStorage。聊天通过预设规则识别委派，不调用语言模型。角色之间的备注过滤只是应用行为；所有数据由同一浏览器访问，绝不构成隐私隔离。

## 目标架构（未实现）

聊天客户端 → 身份认证与 Hub → 持久任务台账 → 受限执行器 → 受控发布模块 → 独立证据核验 → 聊天内人工验收。

- Hub 以确定性代码决定授权和状态，模型仅提出候选动作。
- 私聊与跨人任务上下文分离，只共享经过授权的必要内容。
- Worker 不持有仓库写令牌；发布模块验证租约、合同版本及路径范围。
- 证据与验收绑定当前提交 SHA，任务完成不等于自动合并。
- 外部动作结果未知时先核对，不能盲目重试。
- 日志受控保存、脱敏并设置保留期。

不应将前端模拟状态机直接暴露为生产权限控制。
